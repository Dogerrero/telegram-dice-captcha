# Изменения безопасности и архитектуры

- Убран SQLite: ни состояния капчи, ни пользователи, ни очередь удаления не записываются в базу.
- Состояние активной капчи хранится в памяти только на время текущего процесса; завершённые и вышедшие участники удаляются из состояния.
- Ответ передаётся как выбранное число; правильность проверяется по значению кубика, сохранённому в памяти бота.
- Проверяются целевой пользователь, чат, токен проверки, сообщение, срок действия и текущее состояние; дублированные и устаревшие ответы отклоняются.
- Сохранены тайминги: 120 секунд на капчу, 30 секунд до повтора после неправильного первого ответа, удаление сообщений через 300 секунд и повтор удаления через 60 секунд после ошибки.
- Добавлено администраторское меню `/captcha_settings` с редактированием, просмотром и сбросом приветствия.
- Настройки приветствия сохраняются в JSON, отдельно для каждой разрешённой группы. В JSON не попадают пользовательские ID или статусы капчи.
- README переведён на русский и описывает установку, ограничения хранения и меню администратора.

## Важное ограничение

При перезапуске процесса память очищается. В этом режиме бот не может восстановить незавершённые капчи и очередь удаления; участники, успевшие попасть под ограничение до аварии, могут потребовать ручной проверки.

Публичный результат Telegram-кубика всё ещё доступен userbot-клиентам. Отсутствие правильного ответа в `callback_data` предотвращает простейший обход, но не делает публичный кубик секретным.
